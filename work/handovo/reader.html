Handovo

An AI operations layer for retail stores. The manager states the day’s goal in plain words; the agent turns it into tasks on every staff member’s phone, follows up, and keeps attendance, stock and reports current.

The problem

A store’s day lives in the manager’s head and a noisy WhatsApp group.

Plans don’t reach the floor

The morning huddle sets the day. By noon half of it is forgotten, and nobody can see who was meant to do what.

Every small call goes up

Discounts, counts that don’t match, a broken rail: each one becomes a call or a message the manager has to chase.

AI can’t just be let loose

An agent that messages thirty people needs limits the manager sets, and it must never decide on its own what it is allowed to do.

How might a manager say what today is about once, and trust an agent to run the rest, inside rules they control?

The idea

One goal in. Tasks out to every phone. The manager decides what the agent may do alone.

The agent acts and logs it. Restock tasks, reminders, overdue nudges.

The agent prepares the action and waits for a tap. Sending the day’s plan, counts that don’t add up.

Only the manager can act. Discounts and price overrides, urgent customer issues.

Every rule runs in code after the AI answers. The model only suggests; the engine checks every field and applies the manager’s setting before anything is sent.

Play the day

Two minutes in a 30-person clothing store in Koramangala.

I built the prototype around one scripted Thursday so anyone can feel the system work: a goal, a plan, a discount, a count that’s off, a sell-out, an urgent customer, the handover and the owner’s digest. The control room is on the left; the phone on the right stands in for each staff member’s Handovo app.

01 · The goal

The manager writes one goal

In plain words, the way they’d say it at the morning huddle. No forms. Rain is forecast all week: push rain jackets, count the white linen shirts, keep the fitting rooms tidy.

02 · The plan

The agent drafts the tasks

Eight tasks, each with an owner picked by role, section, shift and current load, and a line saying why. Sending is set to Asks you, so the plan waits for the manager.

03 · The floor

Everyone gets only their own tasks

Meera gets one message with her task and what to reply. Staff answer in the chat they already use, in English, Hindi, Kannada or Malayalam.

04 · A decision

A discount is the manager’s call

Kavya, a cashier, asks for 15% off a rain jacket. Discounts are set to Yours only, so the agent holds the reply and shows why. After approval the answer goes back to Kavya in Kannada, with a few seconds of Undo against a wrong tap.

05 · A mismatch

A count that doesn’t add up

Meera counts 9; the system says 13. A gap over 2 units turns Handles it into Asks you, with the money at stake in plain words.

06 · Handled

Sold out, handled without asking

A size of the navy rain jacket hits zero. Restock is set to Handles it, so Manoj gets the task straight away. Every task keeps its full history.

07 · Urgent

An upset customer always comes up

Rohit flags an angry customer at Footwear. That always reaches the manager, marked urgent, with a banner wherever they are in the app.

08 · The limits

The manager sets the limits

Every rule has three settings. They run in code after the AI answers, so the model never decides what it’s allowed to do. Each decision card says which rule sent it there.

09 · Handover

End of shift

Open work moves to the evening shift with a suggested owner for each task, plus a note for the next shift lead.

10 · Digest

One summary for the owner

Sales against target and a usual Thursday, then counts only. The digest never names or ranks staff.

Design principles

Built so a manager can trust it on day one.

The model suggests, code decides

Claude returns structured JSON. The engine validates every field and applies the manager’s rule. If the AI fails, scripted rules take over.

Always say why

Every card that reaches the manager carries “Why you’re seeing this”, naming the rule that sent it.

No new app for staff

Tasks arrive in the chat staff already use, in their own language, with the reply they need to send.

Watch the work, not the people

Digests count tasks and stock, never rank staff. Messages only go to people who have agreed in writing, as India’s DPDP Act asks.

From prototype to pilot

A working build for one real store.

Manager control room · Today, Needs you, Team, Tasks, Handover, Digest, Stock, Data, Rules, Activity, on a real database (Working)

Routing engine · Handles it / Asks you / Yours only, each with a reason (Working)

Time-driven actions · Check-in reminders, overdue nudges, shift-lead alerts, handover nudge, digest; a scheduler every 5 minutes (Working)

Live AI · Reading staff messages, drafting plans, “Ask the store”, the digest summary (Working)

Languages · English, Hindi, Kannada and Malayalam (Working)

WhatsApp Business Platform · Code ready; waiting on the store’s Meta setup (Phase 2)

Billing (POS) feed · Sales and stock are entered by hand for now (Phase 3)

Next.js, Postgres (Supabase), Claude with structured output, Vercel. The test phone lets anyone rehearse a day before WhatsApp is connected.

What I’d do next

Prove it on the floor.

Run the pilot store for four weeks and measure how many decisions still reach the manager.

Have native readers check every Hindi, Kannada and Malayalam line before staff see it.

Connect the billing system so sales and stock update themselves.

Read the photos staff send back, so “done” can be checked, then deleted after a day.
